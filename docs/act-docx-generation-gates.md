# DOCX Gates для актов

Этот файл обязателен к чтению перед любой новой работой с DOCX-шаблонами актов.
Если любой gate не выполнен, работа останавливается. Запрещено продолжать
"подкруткой" генератора, пробелами, подчёркиваниями или визуальной подгонкой.

## 1. Что запрещено

Запрещено использовать:

1. Символы `_` как линию формы.
2. TextBox, Shape, overlay и координатное наложение текста.
3. Подчёркнутые пробелы как замену линии.
4. Ручную подгонку отступами, табами и пробелами.
5. Автоперенос Word для длинных полей без заранее подготовленных строк.
6. Изменение генератора до принятого PDF-прототипа шаблона.
7. Publish/exe до принятого PDF generated DOCX.

## 2. Правильная структура шаблона

Каждая заполняемая строка должна быть сделана так:

1. Таблица с невидимыми границами.
2. Заполняемая область находится внутри отдельной ячейки.
3. У заполняемой ячейки включена только нижняя граница.
4. Placeholder находится внутри этой ячейки.
5. Ширина ячеек фиксированная.
6. Высота строк фиксированная.
7. AutoFit отключен.
8. Межстрочный интервал и шрифт заданы явно.

Для многострочных полей использовать отдельные placeholders:

1. `{{InspectionWorkDescriptionLine1}}`
2. `{{InspectionWorkDescriptionLine2}}`
3. `{{InspectionWorkDescriptionLine3}}`
4. `{{InspectionResultLine1}}`
5. `{{InspectionResultLine2}}`
6. `{{InspectionResultLine3}}`

## 3. Порядок работ

### Gate 1. Только прототип шаблона

Разрешено:

1. Создать прототип DOCX в `artifacts`.
2. Использовать эталонный DOCX как визуальный источник.
3. Перестроить заполняемые зоны таблицами с нижними границами.

Запрещено:

1. Менять `Templates/Acts`.
2. Менять генератор.
3. Менять тесты.
4. Делать publish/exe.

Проверка:

1. Экспорт прототипа в PDF через Word COM.
2. PNG-рендер PDF.
3. Визуальное сравнение с эталоном.
4. Документ должен быть 1 страница.

Если прототип визуально не похож на эталон, остановиться и дать отчет.

### Gate 2. Перенос принятого шаблона

Разрешено только после принятого Gate 1:

1. Перенести шаблон в `Templates/Acts`.
2. Проверить, что в шаблоне нет `_`, textbox, shape, overlay.

Проверка:

1. Экспорт шаблона из `Templates/Acts` в PDF.
2. PNG-рендер.
3. Визуальное сравнение.

Если шаблон после переноса отличается от принятого прототипа, остановиться.

### Gate 3. Генератор

Разрешено только после принятого Gate 2:

1. Добавить только недостающие placeholders.
2. Добавить заранее рассчитанные `Line1`, `Line2`, `Line3`.
3. Обрезать или переносить длинные данные до вставки в DOCX.

Запрещено:

1. Лечить верстку генератором.
2. Добавлять пробельные хвосты.
3. Добавлять подчёркивания.
4. Подгонять координаты.

Проверка:

1. Targeted tests генератора.
2. Generated DOCX.
3. Экспорт generated DOCX в PDF.
4. PNG-рендер.
5. Визуальное сравнение с эталоном и прототипом.

Если generated DOCX визуально плохой, остановиться. Не делать publish.

### Gate 4. Publish

Разрешено только после принятого Gate 3:

1. `dotnet build`.
2. Publish только через `scripts/publish.ps1`.
3. Файловая проверка `asutpKB.exe`, `act-docx`, шаблонов.
4. Smoke-запуск exe.

В финальном ответе первым указывать полный путь к exe, если exe был собран.

## 4. Стоп-условия

Немедленно остановиться, если:

1. PDF больше одной страницы.
2. Текст оказался рядом с линией, выше линии или ниже линии.
3. Линии сдвинулись относительно эталона.
4. Появились `_` как элементы формы.
5. Появились textbox/shape/overlay.
6. Требуется "чуть подвинуть" пробелами или табами.
7. Нужно менять генератор для исправления геометрии шаблона.
8. Пользователь пишет "стоп", "не меняй", "что делаешь" или аналогичное замечание.

При стопе дать только:

1. Что уже изменено.
2. Какие файлы затронуты.
3. Что проверено.
4. Что не принято.
5. Что нужно откатить или согласовать.

## 5. Обязательный отчет перед продолжением

Перед переходом к следующему gate сообщить:

1. Текущий gate.
2. Разрешенные действия.
3. Запрещенные действия.
4. Артефакты проверки.
5. Результат PDF/PNG проверки.
6. Можно ли идти дальше.

Без явного согласия пользователя переходить к следующему gate запрещено.
