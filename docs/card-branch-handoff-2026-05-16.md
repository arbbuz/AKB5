## Roadmap: карточки установленных объектов из каталога

Решение по направлению работ:

- внедрять разделение понятий:
  - `Каталог оборудования` — справочник типовых моделей;
  - `Карточка установленного объекта` — конкретный объект в дереве с местом установки, инвентарным номером и рабочими данными;
- внедрять сценарий создания объекта дерева из записи каталога;
- не дорабатывать сейчас карточку записи каталога: без новых полей `Серия`, `Тип узла`, `Свойства`;
- не расширять сейчас поиск и таблицу каталога;
- не показывать сейчас скрытые поля правой карточки, если текущая логика формы их скрывает;
- не добавлять сейчас постоянную связь `Состав -> CatalogItemId`, пока она не понадобится отдельной задачей.

Первый этап реализации:

1. Добавить команду `Создать объект из каталога...` для выбранного места в дереве.
2. Переиспользовать существующий диалог выбора оборудования из каталога.
3. После выбора создать новый дочерний узел дерева без изменения модели данных.
4. Заполнять новый узел из каталога минимально:
   - имя узла — из наименования, производителя и заказного номера;
   - тип узла — из существующего `DefaultNodeType`, если он пригоден, иначе `Device`;
   - описание карточки установленного объекта — из описания записи каталога.
5. Сохранить существующие правила дерева: ограничения глубины, undo/redo, dirty-state, обновление UI.

## Решение: уровни дерева и вкладки правой панели

Зафиксирована правильная модель уровней:

- `Lvl1` — отделение, например `Медное отделение`.
- `Lvl2` — система, например `АСУ установкой получения МДК`.
- `Lvl3` — шкаф или щит, например `ШУ`.

Наполнение шкафа или щита не разворачивается в дерево как `Lvl4`. Его рабочее место — правая панель выбранного `Lvl3` на вкладке `Состав`.

Разделение вкладок:

- `Lvl1 Отделение`: `Карточка`.
- `Lvl2 Система`: `Карточка`, `Документация и ПО`, `Сеть`.
- `Lvl3 Шкаф / щит`: `Карточка`, `Состав`, `График ТО`.

Реализация:

- общий признак "инженерного рабочего места" разделен на правила по конкретным вкладкам;
- `Документация и ПО` и `Сеть` доступны на `Lvl2`;
- `Состав` и `График ТО` доступны на `Lvl3`;
- существующие записи `DocumentLinks`, `SoftwareRecords` и `NetworkFileReferences`, которые были привязаны к `Lvl3` или глубже, при нормализации данных переносятся на ближайший родительский `Lvl2`;
- при переносе узла между уровнями очистка типизированных данных теперь выполняется по конкретным вкладкам, а не по одному общему инженерному признаку.
