# Roadmap: Lvl3 `Состав` по Rack

Дата: `2026-05-17`
Ветка: `card`

## Цель

Переработать вкладку `Состав` для `Lvl3` шкафов/щитов так, чтобы наполнение велось справа, без разворачивания в `Lvl4`, и группировалось по Siemens-подобным Rack начиная с `Rack0`.

Ориентир UI: Step 7 / HW Config:

- верхняя область показывает стойки `(0) UR`, `(1) UR`, `(2) UR`;
- внутри стойки есть слотная таблица;
- нижняя область показывает детальную таблицу выбранного Rack/слота;
- `Rack0` является базовым Rack для центральной конфигурации.

## Этап 1. Совместимый гибрид

Статус: реализован локально, ожидает ручной проверки.

- Добавить `RackNumber` в `KbCompositionEntry`.
- Считать существующие слотные записи как `Rack0`.
- Добавить `rack_number` в SQLite `composition_entries` с миграцией старых `.akb`.
- Сохранить JSON-совместимость: отсутствующее поле читается как `0`.
- Протащить `RackNumber` через composition templates и object templates.
- Перестроить `KnowledgeBaseCompositionStateService`: группировка `Rack0+`, slot roles по базовой S7-300 логике.
- Перестроить WinForms экран `Состав`: верхняя область Rack, нижняя детальная таблица выбранного Rack, отдельная вкладка для доп. оборудования.
- Обновить диалог записи состава: выбор `Rack` и `Slot`.

## Этап 2. Siemens-профили и предупреждения

Статус: реализован локально, ожидает ручной проверки.

- Ввести профиль компоновки, сначала `SIMATIC S7-300`.
- Показывать роли слотов:
  - `Rack0`: slot 1 `PS`, slot 2 `CPU`, slot 3 `IM`, slots 4-11 `SM/FM/CP`;
  - `Rack1+`: slot 1 `PS`, slot 2 `Свободен`, slot 3 `IM`, slots 4-11 `SM/FM/CP`.
- Добавить предупреждения без жесткой блокировки, чтобы не мешать реальным шкафам с неполными данными.
- Добавить подсказки по `IM 360/361/365` для расширительных Rack.

Локальная реализация:

- `KnowledgeBaseCompositionRackSlotRulesService` содержит профиль `SIMATIC S7-300`, роли слотов, advisory severity `Hint` / `Warning` и эвристики распознавания `PS`, `CPU`, `IM`.
- `KnowledgeBaseCompositionStateService` добавляет предупреждения и подсказки в rack rows без изменения хранилища.
- Верхняя таблица Rack, нижняя таблица деталей и диалог записи состава показывают колонку/строку `Проверка`.
- Невалидные для профиля позиции не блокируются; пользователь может сохранить реальную компоновку после проверки.

## Этап 3. Полноценная модель Rack

- Добавить отдельную сущность Rack, если потребуется хранить пустые Rack, тип Rack, подписи, порядок, сетевые связи и пользовательские свойства.
- Поддержать пустые стойки без фиктивных компонентов.
- Добавить операции `Добавить Rack`, `Переименовать`, `Удалить пустой Rack`.

## Этап 4. Расширенная аппаратная детализация

- Добавить поля, близкие к нижней таблице Step 7:
  - заказной номер;
  - firmware;
  - MPI/DP/PN адреса;
  - I address;
  - Q address;
  - comment.
- Отдельно рассмотреть subslot/interface rows: `X1`, `X2`, `Port 1`, `Port 2`.
- Связать Rack с будущим развитием вкладки `Сеть`, но не смешивать `Сеть` и `Состав`.

## Правила совместимости

- Не переносить компоненты в `Lvl4` дерева.
- Не удалять существующие `CompositionEntries`.
- Все старые записи без `RackNumber` остаются на `Rack0`.
- Оборудование без слота остается во вкладке `Доп. оборудование`.
- Жесткие Siemens-ограничения добавлять только после ручной проверки первого гибридного UI.
