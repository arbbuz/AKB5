# ТЗ и план реализации переработки меню AKB5

Дата: 2026-05-08
Основание: `docs/menu-command-audit.md`, заполненный `docs/menu-command-audit-questionnaire.md`, уточнения заказчика от 2026-05-08.

Статус на 2026-05-12: шаги 1-6 первой итерации приняты и закоммичены/запушены в `to` как `8dfffbd Rework menu structure and safety prompts`; проверка `menu-rework-stage6` прошла (`340/340`).

## Цель

Снизить визуальную и смысловую перегрузку меню AKB5 без удаления реализованной функциональности из кода. Основная идея первой итерации: оставить пользователю рабочие сценарии, а служебные и опасные операции вынести в отдельное меню `Сервис` или скрыть из меню, сохранив возможность дальнейшей доработки.

## Утверждённые решения

1. Верхнее служебное меню называется `Сервис`, не `Администрирование`.
2. В первой итерации отдельное меню `Цех` не вводится: команды цехов остаются в `Файл`.
3. `ТО` остаётся отдельным верхним меню и должно идти сразу после `Файл`.
4. `Каталог оборудования...` переносится в отдельное верхнее меню `Справочники`.
5. Технические форматы не должны перегружать основные пользовательские названия. Формат оставлять в названии только там, где без него команда становится неоднозначной.
6. Полная замена текущей базы из JSON/Excel должна называться через `Заменить текущую базу...`.
7. Полный Excel-обмен базы скрывается из меню, но код остаётся под капотом для возможной дальнейшей доработки.
8. Импорт производственного календаря JSON скрывается из меню, но код остаётся под капотом.
9. Снимки, восстановление, сравнение и история объединяются в один пользовательский вход `Снимки и история базы...`.
10. Шаблонные команды дерева группируются в подменю `Шаблоны`.
11. Команда добавления верхнего уровня показывается только при клике по пустому месту дерева и называется `Добавить отдел`.
12. Подтверждение перемещения дерева должно показывать изменение уровня `откуда -> куда`, если уровень меняется.
13. Перед опасными операциями должен быть автоматический или предлагаемый снимок базы.
14. Разграничение прав и парольный доступ к `Сервис` нужны в будущем, но не входят в первую итерацию.

## Целевая структура верхнего меню

### `Файл`

Команды первой итерации:

1. `Сохранить`
2. `Открыть базу...`
3. `Сохранить как...`
4. Разделитель
5. `Новый цех`
6. `Удалить цех`
7. `Переименовать цех`
8. Разделитель
9. `Снимки и история базы...`

Поведение:

- `Сохранить` дублирует существующую кнопку панели инструментов.
- `Удалить цех` пока остаётся видимым в `Файл`, но должно получить усиленное подтверждение и предложенный снимок базы.
- `Снимки и история базы...` открывает единый экран/диалог, из которого доступны просмотр, создание снимка, восстановление, сравнение и история изменений.
- Отдельных пунктов `Создать снимок базы...`, `Просмотреть снимки базы...`, `Восстановить из снимка...`, `Сравнить снимки...`, `История изменений...` в верхнем меню быть не должно.
- `Обновить из файла` переносится в `Сервис` и переименовывается.

### `ТО`

`ТО` остаётся отдельным верхним меню сразу после `Файл`.

Целевая структура:

```text
ТО
  Данные для планирования
    Импорт норм ТО...
    План ТО по месяцам...
      Экспорт плана ТО по месяцам...
      Импорт плана ТО по месяцам...
  Производственный календарь
    Производственный календарь...
    Импорт производственного календаря PDF...
  Формирование графиков
    Сформировать график ТО за месяц...
    Сформировать годовой график ТО...
    Пересчитать график ТО до конца года...
```

Допустимая реализация первой итерации: если вложенное подменю `План ТО по месяцам...` неудобно в WinForms, можно сделать три пункта внутри группы `Данные для планирования`:

- `План ТО по месяцам...`
- `Экспорт плана ТО по месяцам...`
- `Импорт плана ТО по месяцам...`

Требования:

- `Редактировать источник годового графика ТО...` переименовать в `План ТО по месяцам...`.
- `Экспорт источника годового графика ТО...` переименовать в `Экспорт плана ТО по месяцам...`.
- `Импорт источника годового графика ТО...` переименовать в `Импорт плана ТО по месяцам...`.
- `Импорт производственного календаря JSON...` убрать из меню.
- `Импорт норм ТО...` остаётся видимым.
- Перед импортом норм ТО предлагать создать снимок базы.

### `Справочники`

Команды первой итерации:

1. `Каталог оборудования...`

Не включать в `Справочники` в первой итерации:

- импорт/экспорт справочников и шаблонов;
- служебные JSON-команды.

Обоснование: по ответам команды импорт/экспорт каталога и шаблонов должны быть в `Сервис`.

### `Сервис`

Служебное меню первой итерации без парольной защиты.

Команды:

1. `Перезагрузить текущую базу из файла...`
2. Разделитель
3. `Экспорт справочников и шаблонов...`
4. `Импорт справочников и шаблонов...`
5. Разделитель
6. `Экспорт текущей базы в JSON...`
7. `Заменить текущую базу из JSON...`

Скрыть из меню, но оставить код под капотом:

- полный экспорт базы Excel;
- полную замену базы из Excel;
- импорт производственного календаря JSON.

Будущая задача:

- парольный доступ к `Сервис`;
- роли или разграничение прав, при котором обычный пользователь не может редактировать базу, менять графики ТО и выполнять критические операции.

## Контекстное меню дерева объектов

### При клике по объекту

Целевая структура:

```text
Добавить сюда
Шаблоны
  Добавить из шаблона состава...
  Создать объект из шаблона...
  Сохранить как шаблон объекта...
  Применить шаблон к объекту...
Копировать
Вставить
Переименовать
Удалить
```

Требования:

- `Добавить на верхнем уровне` не показывать при клике по объекту.
- `Шаблоны` показывать как подменю, а не четырьмя отдельными пунктами.
- Недоступные шаблонные команды можно оставлять disabled, если это не перегружает меню; предпочтительно скрывать недоступные команды после проверки поведения.
- `Удалить` должно получать усиленное подтверждение, если у объекта есть дочерние элементы, профиль ТО или связанные инженерные данные.

### При клике по пустому месту дерева

Целевая структура:

```text
Добавить отдел
Создать объект из шаблона...
```

Требования:

- `Добавить отдел` создаёт объект верхнего видимого уровня текущего цеха.
- `Создать объект из шаблона...` доступно только если есть шаблоны, которые можно вставить в корень текущего цеха.
- Команды `Копировать`, `Вставить`, `Переименовать`, `Удалить`, `Добавить сюда` не показывать без выбранного объекта.

## Перемещение объектов мышью

Существующее подтверждение перемещения оставить и расширить.

Новое окно подтверждения должно показывать:

- имя перемещаемого объекта;
- старого родителя;
- нового родителя;
- старый видимый уровень;
- новый видимый уровень;
- отдельное предупреждение, если уровень меняется.

Пример текста:

```text
Переместить объект "АСУ ..."?

Было:
Родитель: Никелевое отделение
Уровень: Lvl3

Станет:
Родитель: Склад сырьевой серной кислоты
Уровень: Lvl2

При смене уровня объект примет свойства нового уровня. Продолжить?
```

Требования:

- кнопка по умолчанию должна быть `Нет`.
- при смене уровня нужно явно сообщать, что объект примет свойства нового уровня.
- логика перебазирования свойств при перемещении должна сохраняться.

## Защитные снимки и подтверждения

Перед следующими операциями нужен автоматический или предлагаемый снимок:

1. `Заменить текущую базу из JSON...`
2. Полная замена базы из Excel, если команда будет вызвана служебно или вернётся в интерфейс.
3. `Импорт норм ТО...`
4. `Восстановить из снимка` внутри окна `Снимки и история базы...` - защитный снимок уже должен создаваться перед восстановлением.
5. `Удалить цех`
6. Массовое применение шаблона к объекту, если операция затрагивает несколько узлов или связанные данные.

Рекомендуемый диалог перед опасной операцией:

```text
Перед операцией рекомендуется создать снимок базы.

[Создать снимок и продолжить]
[Продолжить без снимка]
[Отмена]
```

Для восстановления из снимка вариант `Продолжить без снимка` не нужен: защитный снимок должен создаваться автоматически.

## План реализации

### Шаг 1. Перестроить верхнее меню

Файлы-кандидаты:

- `Forms/MainForm.cs`
- `Forms/MainForm.Layout.cs`
- `Forms/MainForm.Events.cs`
- `UiServices/KnowledgeBaseFileUiWorkflowService.cs`

Работы:

- добавить `menuService` и `menuReferences`;
- добавить пункт `Сохранить` в `Файл`;
- оставить команды цехов в `Файл`;
- перенести служебные команды в `Сервис`;
- убрать из меню полный Excel-обмен и JSON-импорт производственного календаря;
- объединить вход в снимки и историю.

### Шаг 2. Объединить снимки и историю

Файлы-кандидаты:

- `UiServices/KnowledgeBaseFileUiWorkflowService.cs`
- формы снимков и истории в `Forms/`

Работы:

- сделать единый пункт `Снимки и история базы...`;
- из одного окна дать доступ к созданию снимка, восстановлению, сравнению и истории;
- если существующий браузер снимков уже поддерживает восстановление и сравнение, расширить его или добавить рядом доступ к истории;
- убрать отдельные пункты верхнего меню.

### Шаг 3. Перестроить меню `ТО`

Файлы-кандидаты:

- `Forms/MainForm.Layout.cs`
- `Forms/MainForm.Maintenance.cs`
- `Forms/MainForm.ProductionCalendar.cs`

Работы:

- разбить команды по группам;
- переименовать источник годового графика в план ТО по месяцам;
- убрать JSON-импорт производственного календаря из меню;
- добавить предложение снимка перед импортом норм ТО.

### Шаг 4. Перестроить контекстное меню дерева

Файлы-кандидаты:

- `Forms/MainForm.Layout.cs`
- `Forms/MainForm.cs`
- `Forms/MainForm.Events.cs`
- `UiServices/KnowledgeBaseTreeMutationUiWorkflowService.cs`
- `Services/KnowledgeBaseTreeMutationWorkflowService.cs`

Работы:

- разделить контекстное меню для клика по объекту и по пустому месту;
- переименовать верхнее добавление в `Добавить отдел`;
- показывать `Добавить отдел` только на пустом месте дерева;
- сгруппировать шаблонные команды в подменю `Шаблоны`;
- усилить подтверждение удаления объекта при наличии дочерних или связанных данных.

### Шаг 5. Улучшить подтверждение перемещения

Файлы-кандидаты:

- `UiServices/KnowledgeBaseTreeMutationUiWorkflowService.cs`
- `Services/KnowledgeBaseTreeMutationWorkflowService.cs`
- возможно `UiServices/KnowledgeBaseTreeViewService.cs`

Работы:

- вычислять старый и новый видимый уровень;
- показывать старого и нового родителя;
- показывать `LvlX -> LvlY`, если уровень меняется;
- явно предупреждать о смене свойств уровня;
- оставить кнопку по умолчанию `Нет`.

### Шаг 6. Защитные снимки перед опасными операциями

Файлы-кандидаты:

- `UiServices/KnowledgeBaseFileUiWorkflowService.cs`
- `Forms/MainForm.Maintenance.cs`
- `UiServices/KnowledgeBaseWorkshopUiWorkflowService.cs`
- `UiServices/KnowledgeBaseTreeMutationUiWorkflowService.cs`

Работы:

- выделить общий helper для предложения снимка перед опасной операцией;
- подключить helper к замене базы из JSON, импорту норм ТО, удалению цеха, массовому применению шаблона;
- проверить существующее защитное поведение восстановления из снимка.

## Проверка

Минимальная проверка после реализации:

1. Сборка Release.
2. Целевые тесты для tree mutation workflow.
3. Тесты file workflow/snapshot/history, если затронуты сервисы снимков.
4. Тесты maintenance norm import, если изменяется импорт норм ТО.
5. Ручная проверка меню:
   - порядок верхних меню: `Файл`, `ТО`, `Справочники`, `Сервис`;
   - в `Файл` нет JSON/Excel-служебных команд;
   - в `ТО` нет JSON-календаря;
   - полный Excel базы не виден;
   - шаблоны дерева находятся в подменю;
   - `Добавить отдел` виден только при клике по пустому месту;
   - перемещение показывает `откуда -> куда`;
   - опасные операции предлагают снимок или создают защитный снимок.

## Не входит в первую итерацию

- Пароль на меню `Сервис`.
- Полноценные роли пользователей.
- Запрет редактирования базы обычному пользователю.
- Удаление кода полного Excel-обмена.
- Удаление кода JSON-импорта производственного календаря.
- Переработка прав доступа к вкладкам карточки, состава, документации, сети и ТО.

## Критерии готовности

Задача считается выполненной, если:

- меню соответствует утверждённой структуре первой итерации;
- служебные форматы и опасные операции больше не перегружают основной `Файл`;
- команды ТО сгруппированы по рабочим стадиям;
- контекстное меню дерева стало короче и шаблоны сгруппированы;
- перемещение дерева показывает изменение уровня;
- перед опасными операциями есть снимок или предложение снимка;
- существующие сценарии не потеряны из кода, если по ТЗ они должны остаться под капотом.
